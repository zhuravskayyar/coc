# Сітка й стартова база

Єдина логічна квадратна сітка — 44×44 клітинки. На екрані вона показана ізометрично: одна клітинка — ромб 96×72 світових пікселів. `cell` будівлі — перша клітинка її площі: `cell.x` відповідає `gridX`, `cell.y` — `gridY`. Будівлі прив'язуються до цілих координат.

Єдине джерело розмірів у коді — `scripts/building_catalog.gd`.

| Будівля | Площа |
| --- | --- |
| Головний храм / ратуша | 4×4 |
| Будиночок будівельника | 2×2 |
| Воєнна палатка | 3×3 |
| Табір юнітів | 5×5 |
| Шахта золота Lv.1 | 3×3 |
| Сховище золота | 3×3 |
| Збирач хліба, наступний етап | Розмір визначимо під час розробки |
| Сховище хліба, наступний етап | Розмір визначимо під час розробки |
| Стартова оборонна башта | 2×2 |
| Секція дерев’яного частоколу | 1×1 |
| Пастка, пізніше | 1×1 |
| Малий / великий декор | 1×1 / 2×2 |

1×1 — секції, пастки й декор; 2×2 — малі виробничі та оборонні споруди; 3×3 — звичайні будівлі; 4×4 — ключові великі будівлі; 5×5 — спеціальні майданчики.

## Спрайти й трава

Спільний ground anchor всіх будівель — **центр footprint на землі**, локальна точка `(0, 0)` вузла будівлі. Позицію задає тільки `VillageMap.get_footprint_center(cell, footprint)` через спільну `grid_to_world`. Формула координат центру в сітці: `cell + (footprint - 1) / 2`. Довільні зміни позиції, повороту чи масштабу вузла відразу повертаються до трансформації сітки; розміщення змінюється через `cell`.

`get_footprint_polygon` обчислює краї площі та трав'яного майданчика через ту саму проєкцію. Ручних координат `ground_bottom` чи окремих зміщень спрайтів у каталозі немає.

Площа будівлі не залежить від розміру PNG, прозорих полів, висоти даху або декоративної трави. Центр землі всередині PNG визначається спільним алгоритмом: передня точка опори береться з вузької смуги нижнього непрозорого контуру (альфа від 0,5), після чого центр площини обчислюється з її ширини та проєкції сітки. Слабкі артефакти альфа-каналу і прозорі поля не впливають на anchor. Результат кешується для кожної текстури.

`source_ground_width` описує ширину основи у вихідному PNG і зберігає попередній рівномірний масштаб спрайтів. Індивідуальних поправок масштабу, повороту чи перспективи немає. Алгоритм точно прив'язує опору до сітки, але не змінює намальований контур: сходи, виступи та відмінності перспективи вихідних PNG не стають геометрично правильним ромбом від зміни anchor. Для повного збігу всіх країв нові спрайти слід малювати під спільну проєкцію 96:72 та центр footprint на землі.

Під кожною будівлею є суцільний квадратний майданчик щільнішої зеленої трави, прив'язаний до тієї самої сітки. В ізометрії він виглядає ромбом. За уточненням користувача відступ у **0,5 клітинки розташований зовні** зайнятої площі: трав'яна основа храму — 5×5 при зайнятій площі 4×4, палатки, шахти й сховища — 4×4 при 3×3, табору — 6×6 при 5×5.

Майданчик використовує наявну текстуру поля через `assets/shaders/building_grass.gdshader`. Його прозорість плавно змінюється в зовнішній смузі 0,5 клітинки, тому немає різкого зеленого краю. Окремі пучки високої трави навколо будівель і частоколу не малюються. Усі трав'яні основи залишаються під будівлями й сіткою розміщення.

Для частоколу підкладка продовжує колір землі з PNG й плавно змішує його з травою. Колір береться зі спільної ділянки біля переднього кута основи та кешується для кожної текстури. `assets/shaders/palisade_soil.gdshader` також пом'якшує передній край ґрунту й його темну обводку. Дерев'яні стовпи, рейки та підняті основи інших будівель зберігають чіткість; оригінальні PNG не змінюються.

Трав'яний край не збільшує зайняту площу й не блокує ходьбу чи будівництво. Сусідню будівлю можна поставити впритул за логічною сіткою.

Оригінальні PNG користувача з прозорим фоном збережено без змін у `assets/sprites/buildings/`.

## Табір

Усі 25 клітинок табору зайняті для розміщення: іншу будівлю всередині поставити не можна. Для майбутнього пересування юнітів центральний квадрат 3×3 має прохідне кільце з восьми клітинок навколо вогнища; край із декором заблокований. Вогнище в клітинці `(2, 2)` блокує свою центральну клітинку. Клітинка `(2, 4)` відносно початку табору — прохід на нижньому лівому боці, який з'єднує середину з полем.

```text
X X X X X
X . . . X
X . F . X
X . . . X
X X E X X
```

`X` — край із декором, `.` — прохідне кільце, `F` — вогнище, `E` — вхід. Для ходьби й розміщення використовуються окремі перевірки: `is_walkable_cell` і `can_place_building`. `find_cell_path` шукає маршрут на тій самій сітці та обходить вогнище.

Вогнище — окремий спрайт усередині табору, а не ще одна будівля: воно не збільшує зайняті 5×5. Його позиція обчислюється з `campfire_cell` через ту саму сітку, а точка опори PNG — через спільний алгоритм ground anchor. Грунт табору має глобальний шар 17; окреме вогнище — шар 30, як будівлі та майбутні юніти. Це дозволяє згодом малювати юнітів поверх грунту. Трав'яна підкладка з плавним краєм займає зовнішній відступ 0,5 клітинки.

За уточненням користувача навчання, вигляд, рух та анімації юнітів залишені на наступний етап. У цій зміні підготовлено спрайти, місце вогнища та прохідне кільце без кнопок навчання й створення юнітів.

## Старт

Повна стартова база: по одному храму 4×4, воєнній палатці 3×3, табору 5×5, шахті золота 3×3 й сховищу золота 3×3, а також два будиночки будівельників 2×2, усі Lv.1. Внутрішній тип `gold_extractor` у каталозі тепер означає шахту 3×3.

У поточній сцені показані всі сім будівель стартової бази з готовими спрайтами:

| Будівля | Перша клітинка | Рівень |
| --- | --- | --- |
| Храм | (20, 20), центр площі точно в центрі карти | 1 |
| Воєнна палатка | (26, 19) | 1 |
| Табір | (20, 26) | 1 |
| Шахта золота | (14, 21) | 1 |
| Сховище золота | (26, 24) | 1 |
| Будиночок будівельника 1 | (18, 14) | 1 |
| Будиночок будівельника 2 | (21, 14) | 1 |

Разом стартові будівлі резервують 76 клітинок: 16 + 9 + 25 + 9 + 9 + 4 + 4. Шахта й сховище займають по дев’ять клітинок, кожен будиночок будівельника — чотири; вони блокують пересування всередині своєї площі. Спрайти використовують спільну прив’язку до центру землі та рівномірний масштаб за шириною основи. Будиночок доступний у категорії «Інше» та використовує наявні вибір, інформацію й переміщення. Система зайнятості будівельників, їхні юніти й анімації ще не реалізовані.

Наступні будівлі розробляємо по одній, у такому порядку: **збирач хліба → сховище хліба → перша оборонна башта → дерев’яний частокіл**. Розміри хлібних будівель визначимо на їхньому етапі. Перша стіна — дерев’яна секція 1×1; для початку заплановано приблизно 10 секцій. Ці будівлі гравець поставить сам після короткого навчання, вони не додаються до готової стартової сцени.

Перший цикл: **храм → палатка → перші юніти → табір → золото → перша атака → хліб → оборона → апгрейд храму**. Це зафіксований порядок майбутнього навчання; економіка, навчання, атаки й апгрейди поки не реалізовані.

## Частокіл

Частокіл 1×1 має 16 спрайтів для всіх комбінацій сусідів. Секції автоматично з’єднуються по чотирьох сторонах сітки після додавання, прибирання або зміни `cell`. Клавіша W вмикає розміщення; лівий клік ставить секцію, Shift + клік прибирає, Esc завершує. [Набір спрайтів, схема та перевірки](palisade-connections.md).
